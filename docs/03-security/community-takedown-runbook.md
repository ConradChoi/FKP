# 게시물 게시중단 요청(임시조치) 운영 런북

| 항목 | 내용 |
|---|---|
| 목적 | 리뷰·커뮤니티 게시물로 권리를 침해받았다는 제3자(공급사 포함)의 요청을 정보통신망법 제44조의2와 이용약관 제11조의3에 맞게 처리 |
| 접수 창구 | info@ylia.io (안내 화면: /seepn/legal/takedown) |
| 작성일 | 2026-09-26 |
| 상태 | **초안 — 변호사 검토 필요**(임시조치 요건·기한·통지 방식). 내부 문서, 대외 공개 금지 |

## 처리 절차
1. **접수 확인**: 요청서에 (1) 요청인 성명·연락처·권리자 확인 정보 (2) 게시물 위치 (3) 소명 내용·자료가 있는지 확인. 부족하면 보완 요청(이 동안에도 명백한 침해라면 먼저 조치).
2. **즉시 임시조치**: admin > 리뷰 탭(공급사 상세) 또는 커뮤니티 운영에서 해당 게시물을 **숨김** 처리하고 사유란에 `임시조치: 요청 접수 YYYY-MM-DD, 만료 YYYY-MM-DD(30일)`를 기록한다. 리뷰는 숨김 시 (공급사, 작성자) 조합이 차단되어 재작성해도 재게시되지 않는다.
3. **통지**: 요청인과 게시물 작성 회원(가입 이메일)에게 조치 사실을 알린다. 작성 회원에게는 이의·재게시 요청 방법(info@ylia.io)과 기한(임시조치 30일)을 안내한다. **작성 회원의 신원을 요청인에게 알려주지 않는다**(공급사에도 마찬가지).
4. **판단**: 작성 회원의 이의가 있으면 양측 소명을 검토해 삭제 또는 재게시를 결정한다. 판단이 어려우면 변호사에게 문의한다.
5. **종결**: 삭제 시 게시물 삭제(회원 계정 조치는 별도), 재게시 시 숨김 해제. 결과를 양측에 통지하고, 접수·조치·통지 일시를 기록한다(숨김 이력은 `partner_review_moderation_log`, `community_moderation_log`에 남고, 통지·소명 내용은 별도 기록 보관).
6. **기한 관리**: 임시조치 만료일(30일)을 넘기지 않도록 만료 전에 결정한다. 만료 시 자동 재게시되지 않으므로 담당자가 직접 결정·처리한다.

## 기록 항목(접수 대장)
접수일시, 요청인, 대상 게시물 위치, 조치 일시·조치자, 통지 일시(요청인·작성자), 이의 여부, 최종 판단·일시.

## 참고
- 신고자·작성자 정보는 이 절차 밖으로 나가지 않는다(처리방침 제6조 '파트너가 알 수 없는 것').
- 수사기관의 자료 제공 요청은 이 절차가 아니라 적법한 절차(영장 등)가 있을 때만 별도로 대응한다.
