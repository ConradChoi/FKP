# Admin "AI 초벌 채우기" — 최종 카피

> 원본 화면 정의서: [admin-ai-translation-draft.screen-spec.md](./admin-ai-translation-draft.screen-spec.md)
> 이 문서는 그 문서 §2.1/§2.2/§4/§5.1의 "안(案)" 문구를 최종 카피로 확정한다. § 번호는 원본 문서 기준.

## 0. 톤 기준 (기존 화면에서 확인함)

`CategoryRow.tsx`, `ArticleRow.tsx`, `FaqRow.tsx`의 기존 `window.confirm`/에러 문구를 참고해 아래 규칙을 그대로 따른다.

- 느낌표 남용 금지, 확인창은 "① 지금 상황 → ② 이 행동을 하면 벌어질 일 → ③ 계속할지 질문(~할까요?)" 3단 구조.
- 상태값 라벨은 화면에 이미 있는 단어를 그대로 쓴다: `초안` / `작성완료` / `게시됨`. **"발행"이라는 단어는 쓰지 않는다** — 스펙 초안에 "발행"이 섞여 있었으나 실제 드롭다운 라벨은 "게시됨"이므로 전부 "게시"로 통일했다(아래 표 반영 완료).
- 원본 로케일 카드는 이미 `"English (원본)"`처럼 라벨링되어 있으므로 에러 문구에서도 "원본"을 그대로 쓴다.
- `window.confirm`은 버튼 텍스트를 "확인/취소"에서 바꿀 수 없다(브라우저 네이티브). 문구만으로 경고 강도를 전달해야 한다.

## 2. §2.1 — AI 초벌 채우기 확인창 (Tier 1/2/3)

세 문구는 강도가 다르게 읽혀야 한다. Tier 1→3으로 갈수록 문장 길이·구체성·경고 표시(⚠)를 단계적으로 올렸다.

| Tier | 조건 | 최종 카피 |
|---|---|---|
| 🟡 Tier 1 | 기존 값 있음, `translation_source='ai'`(미검수) | **이미 AI 초안이 있습니다. 새로 받으면 지금 내용을 덮어씁니다. 계속할까요?** |
| 🟠 Tier 2 | 기존 값 있음, `status≠published`, `translation_source`가 `human`/`ai_reviewed` | **사람이 직접 작성했거나 검수를 마친 번역입니다. AI 초안으로 다시 채우면 이 내용이 사라집니다. 계속할까요?** |
| 🔴 Tier 3 (최우선) | 기존 값 있음, `status='published'` | 아래 §2.1-A 참고 |

### 2.1-A. Tier 3 (게시 중 콘텐츠 강등 경고) — 두 옵션

이 확인창은 실수하면 실제 라이브 화면이 깨지는 유일한 지점이므로 별도로 다룬다.

**옵션 A (권장, `window.confirm` 그대로 사용, 멀티라인)**

```
⚠ 지금 사이트에 게시 중인 {locale} 번역입니다.
AI 초안으로 다시 채우면 상태가 즉시 '초안'으로 바뀌며 화면에서 내려갑니다(비공개).
다시 게시하려면 내용을 검수한 뒤 상태를 '게시됨'으로 바꿔 다시 저장해야 합니다.

계속할까요?
```

- `{locale}`은 카드가 이미 갖고 있는 로케일 라벨(`"日本語"`/`"English"` 등)을 그대로 삽입 — 컴포넌트가 이미 이 값을 prop으로 들고 있어 추가 조회 없이 삽입 가능(frontend-developer 구현 비용 거의 없음).
- "초안"/"게시됨"이라는 정확한 상태 드롭다운 라벨을 그대로 인용해, 운영자가 "아, 그 드롭다운 값이 바뀌는 거구나"라고 즉시 연결 짓게 함.
- "다시 게시하려면 ~해야 합니다"를 넣어 이게 원클릭으로 되돌릴 수 없는 일이라는 것을 분명히 함(이번 확인창 자체가 유일한 안전장치라는 인식을 줌).

**옵션 B (한 줄, Tier 1/2와 길이 형식을 맞추고 싶을 때)**

```
⚠ 지금 게시 중인 {locale} 번역입니다. 다시 받으면 상태가 즉시 '초안'으로 바뀌어 화면에서 내려갑니다. 계속할까요?
```

**권장: 옵션 A.** Tier 3만 유독 문장이 길어지는 게 어색해 보일 수 있지만, 이건 "리스크에 비례해 마찰을 늘린다"는 의도적 설계이며, 나머지 세 화면(랜딩카피/CMS카테고리/게시판)에서 동일하게 재사용되는 하나의 문자열이라 유지보수 비용도 낮다.

**추가 권고(문구 범위를 넘는 제안, ui-ux-designer/frontend-developer 검토 요청):** Tier 3만큼은 브라우저 기본 `confirm()` 대신, "확인" 버튼을 빨간색으로 강조한 커스텀 모달로 격상하는 것을 고려할 만하다. 그 경우를 대비한 모달용 카피:

| 요소 | 카피 |
|---|---|
| 제목 | 게시 중인 번역을 덮어쓸까요? |
| 본문 | 지금 사이트에 게시 중인 {locale} 번역입니다. AI 초안으로 다시 채우면 상태가 즉시 '초안'으로 바뀌며 화면에서 내려갑니다(비공개). 다시 게시하려면 내용을 검수한 뒤 상태를 '게시됨'으로 바꿔 다시 저장해야 합니다. |
| 취소 버튼 | 취소 |
| 확인 버튼(빨간 강조) | 그래도 다시 받기 |

이건 Should — `window.confirm`으로도 옵션 A 문구면 요구 강도는 충족한다.

## 3. §2.2 — 저장 시 검수완료 승격 확인창

"왜 이 확인창이 뜨는지"를 설명하지 않고, "지금 이 내용을 확인했다고 표시할지"를 직접 묻는 데 집중했다(지시사항 반영).

| 버전 | 카피 | 비고 |
|---|---|---|
| **옵션 A (권장)** | **저장하면 이 번역이 '검수완료'로 표시됩니다. 내용을 확인한 것으로 표시할까요?** | 뒤에 이어지는 효과(게시 가능해짐)를 설명하지 않고 "확인했다고 표시할지"에만 집중 — 지시사항과 가장 정확히 일치. |
| 옵션 B | 저장하면 '검수완료'로 표시되어 게시할 수 있게 됩니다. 내용을 확인했나요? | 게시 가능해진다는 결과까지 알려줘 나중에 "게시됨 옵션이 왜 갑자기 활성화됐지?"라는 문의를 줄일 수 있음. 다만 지시사항이 요구한 "설명하지 말고 확인만 물어라"는 원칙에서는 한 발 벗어남. |

**권장: 옵션 A.** (원안의 "내용을 확인하셨습니까?"는 이 화면 다른 곳의 confirm 어미("~할까요?")와 어긋나 존댓말 톤이 붕 뜨므로 어미를 통일했다.)

### 3.1 파생 에러 — AI 초안 상태에서 "게시됨"으로 저장 시도가 서버에서 거부될 때

§5.2에서 "게시됨" 옵션을 클라이언트에서 비활성화하지만, 방어적으로 서버도 거부한다. 그 경우의 에러 문구:

> **AI 초안 상태에서는 게시할 수 없습니다. 먼저 내용을 검수한 뒤 다시 저장해주세요.**

(원안 "AI 초안은 검수 후에만 발행할 수 있습니다"에서 "발행"→"게시"로 교정, "다시 저장해주세요"를 붙여 다음 행동을 명시.)

## 4. §4 — 엣지케이스 에러 메시지 전체 (기술 용어 제거)

기술 용어(`TIMEOUT`, `RATE_LIMITED`, `EMPTY_SOURCE` 등)는 화면에 노출하지 않는다. 아래 표는 `errorCode`(§6.1) → 실제 노출 문구 매핑이며, backend-developer/frontend-developer가 그대로 참조 가능하도록 코드값을 남겨둔다.

| errorCode | 상황(§4 번호) | 노출 위치 | 최종 카피 |
|---|---|---|---|
| `EMPTY_SOURCE` | E-1 | 버튼 비활성 툴팁 + (우회 시) 서버 거부 에러 | **원문이 비어 있어 번역할 수 없습니다. 원본 카드에 내용을 먼저 입력해주세요.** |
| `SOURCE_TOO_LONG` | E-2 | 버튼 비활성 툴팁 + (우회 시) 서버 거부 에러 | **{필드명}이(가) 너무 깁니다({N}자 / 최대 20,000자). 원문을 줄이거나 직접 입력해주세요.** — {필드명} 매핑은 §4.1 참고 |
| `TRANSLATE_TIMEOUT` | E-7 | 카드 내 에러 영역 | **번역 서비스 응답이 늦어지고 있습니다. 잠시 후 다시 시도해주세요.** |
| `RATE_LIMITED` | E-8 | 카드 내 에러 영역 | **번역 요청이 많아 일시적으로 제한되었습니다. 잠시 후 다시 시도해주세요.** |
| `TRANSLATE_API_ERROR` | E-9 | 카드 내 에러 영역 | **번역 서비스에서 오류가 발생했습니다. 잠시 후 다시 시도하거나 직접 입력해주세요.** |
| `ACCESS_DENIED` | E-10 | 카드 내 에러 영역 | **권한이 없거나 로그인이 만료되었습니다. 다시 로그인해주세요.** |
| `CONFIG_ERROR` | (§6.1에만 존재, §4 표엔 없던 코드) | 카드 내 에러 영역 | **번역 기능에 일시적인 문제가 있어 사용할 수 없습니다. 개발팀에 문의해주세요.** — 운영자가 스스로 해결할 수 없는 설정 오류이므로 "잠시 후 재시도"가 아니라 문의를 안내 |
| `CASE_STUDY_NOT_ALLOWED` | E-15 | (평소 노출 안 됨 — 버튼 자체가 렌더링되지 않으므로 방어적 코드 경로에서만 발생) | **사례 콘텐츠는 AI 번역 대상이 아닙니다.** |
| `INVALID_TARGET_LOCALE` | (§6.1에 없던 코드, qa-review 2026-09-08 이후 backend-developer가 추가 — 원본 로케일을 대상으로 지정하는 우회 호출 방어용, 평소 노출 안 됨) | 카드 내 에러 영역 | **원본 로케일은 번역 대상으로 지정할 수 없습니다.** — 정상 UI 흐름에서는 발생하지 않고 방어적 코드 경로에서만 발생 |
| `SAVE_FAILED` | (§6.1에 없던 코드, backend-developer가 추가 — 원문 조회/번역/DB 저장 등 번역 API 호출 전후 여러 단계에서 발생 가능한 저장 실패의 통칭. 2026-09-08 qa-review에서 "번역은 완료" 문구가 번역 호출 이전 실패 케이스와 안 맞는다는 지적을 받아 문구를 일반화함) | 카드 내 에러 영역 | **AI 초벌 채우기에 실패했습니다. 다시 시도해주세요.** |
| *(매칭 실패/네트워크 단절 등 알 수 없는 실패)* | — | 카드 내 에러 영역 | **AI 초벌 채우기에 실패했습니다. 잠시 후 다시 시도해주세요.** — errorCode가 위 목록 어디에도 없을 때의 기본값(fallback) |

세 문구(E-7/8/9) 모두 "잠시 후 다시 시도" 어순을 앞에 두고, 되는 경우에만 "직접 입력" 대안을 뒤에 붙이는 순서로 통일했다(원안은 순서가 문구마다 달랐음).

### 4.1 §1.4 필드명 매핑 (`SOURCE_TOO_LONG`용)

다중 필드 카드에서 "어느 필드가 초과했는지"를 알려주려면 필드 라벨이 필요하다. 각 화면의 기존 `placeholder` 문구와 동일한 단어로 통일했다(신규 용어 만들지 않음).

| 화면 | API 필드명 | 노출 라벨 | 완성 문구 예시 |
|---|---|---|---|
| 랜딩 카피 | `text` | 텍스트 | 텍스트가 너무 깁니다(23,481자 / 최대 20,000자). 원문을 줄이거나 직접 입력해주세요. |
| CMS 카테고리 / 표준 카테고리 | `name` | 카테고리명 | 카테고리명이 너무 깁니다(...). ... |
| CMS 카테고리 | `keywords` | 키워드 | 키워드가 너무 깁니다(...). ... |
| 게시판 FAQ | `question` | 질문 | 질문이 너무 깁니다(...). ... |
| 게시판 FAQ | `answer` | 답변 | 답변이 너무 깁니다(...). ... |
| 게시판 블로그 | `title` | 제목 | 제목이 너무 깁니다(...). ... |
| 게시판 블로그 | `excerpt` | 요약 | 요약이 너무 깁니다(...). ... |
| 게시판 블로그 | `bodyMarkdown` | 본문 | 본문이 너무 깁니다(23,481자 / 최대 20,000자). 원문을 줄이거나 직접 입력해주세요. |

## 5. §5.1 — 배지 라벨 (Gap G-3 해소용, `computeSourceBadge`)

### 5.1-A 용어 충돌 수정: "초안" 재사용 금지

원안 라벨은 **"AI 초안 · 미검수"** / **"AI 초안 · 검수완료"**였다. 문제: 같은 카드 안 상태 드롭다운에 이미 `초안`이라는 옵션(콘텐츠 상태 `status='draft'`)이 존재한다. 두 배지가 나란히 뜨면(§5.1 명시: "번역완료" + "AI 초안·미검수"처럼 동시 노출 가능) `초안`이라는 같은 단어가 "콘텐츠 상태"와 "번역 출처"라는 서로 다른 두 개념을 동시에 가리키게 되어, 운영자가 한눈에 구분하기는커녕 오히려 헷갈릴 수 있다. **번역 출처 배지에서는 "초안" 대신 "번역"을 쓴다.**

| `translation_source` | 노출 여부 | 최종 라벨 | 톤 |
|---|:---:|---|---|
| `human`(또는 행 없음) | 노출 안 함 | — | — |
| `ai` | 노출 | **AI 번역 · 미검수** | `warning`(주황) |
| `ai_reviewed` | 노출 | **AI 번역 · 검수완료** | `info`(파랑) |

### 5.1-B 더 짧은 대안 (목록이 좁아 줄바꿈이 걱정될 때)

| `translation_source` | 라벨 |
|---|---|
| `ai` | **AI 미검수** |
| `ai_reviewed` | **AI 검수완료** |

이미 옆에 로케일(`JA`)·상태(`게시됨` 등) 배지가 붙어 있어 문맥이 충분하므로 "번역"을 생략해도 의미가 통한다. 목록 화면(요약 행)에는 5.1-B, 펼친 편집 카드 내부처럼 공간 여유가 있는 곳에는 5.1-A를 쓰는 것을 권장한다 — 최종 선택은 ui-ux-designer의 레이아웃 시안에 맞춰 결정.

### 5.2 상태 드롭다운 가드 툴팁

원안 "AI 초안은 검수 후에만 발행할 수 있습니다"에서 "발행"→"게시"로 교정.

> **AI 초안은 검수 후에만 게시할 수 있습니다.**

(이 문장 안의 "AI 초안"은 배지 라벨이 아니라 "AI가 만든, 아직 검수 전인 콘텐츠"를 가리키는 일반 서술이라 문제되지 않는다 — 배지처럼 고정 라벨로 반복 노출되는 게 아니라 툴팁 한 번성 문장이라 혼동 위험이 낮음.)

## 6. 용어집 (이번 기능 한정)

| 개념 | 통일 단어 | 쓰지 않을 단어 |
|---|---|---|
| 콘텐츠 상태 `status='draft'` | 초안 (드롭다운 라벨, 기존 유지) | — |
| 콘텐츠 상태 `status='published'` | 게시됨 / 게시 중 / 게시 | 발행 |
| 번역 출처가 AI인 것 (배지) | AI 번역 | AI 초안 (드롭다운의 "초안"과 충돌) |
| 번역 원문이 있는 로케일 | 원본 (기존 UI 라벨 `"English (원본)"` 그대로) | — |
| 번역할 대상 텍스트 그 자체 | 원문 | — |
| 로그인 세션 문제 | 로그인이 만료됨 | 세션 (비개발자 대상 화면이라 순화) |

## 7. 구현 참고사항 (frontend-developer)

- `window.confirm`은 버튼 라벨을 바꿀 수 없다 — 문구만으로 강도를 전달해야 하며, 위 Tier 3 옵션 A처럼 멀티라인(`\n`, `\n\n`)을 그대로 문자열에 넣어도 브라우저가 줄바꿈을 렌더링하므로 문제없다.
- Tier 3 문구의 `{locale}`은 각 컴포넌트가 이미 갖고 있는 `label`/`localeLabel` prop을 그대로 삽입하면 된다(추가 API 호출 불필요).
- `SOURCE_TOO_LONG` 문구의 `{필드명}`/`{N}`은 §4.1 표의 라벨과 서버가 반환하는 `field`/`actualLength`를 그대로 조합.
- §4 표의 "기본값(fallback)" 문구는 `errorCode`가 정의되지 않은 응답(예: fetch 자체 실패)에 대한 안전망으로 반드시 넣어둘 것 — 사용자가 빈 에러나 `undefined`를 보는 상황을 방지.

## 8. qa-reviewer 확인 포인트

- Tier 3 확인창 취소 시 정말 아무 일도 안 일어나는지(§2.1 diagram "Z: 아무 동작 없음"), 특히 게시 중인 콘텐츠가 취소 후에도 그대로 게시 상태로 남아있는지.
- "게시됨" 옵션이 `translation_source='ai'`일 때 실제로 드롭다운에서 선택 자체가 안 되는지, 그리고 만약 우회 경로로 시도됐을 때 §3.1 에러 문구가 정확히 뜨는지.
- 배지 라벨에 "초안"이라는 단어가 실수로 다시 들어가지 않았는지(구현 중 재도입 방지).
